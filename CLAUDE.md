## Project Overview

SwanLab-Server is a machine learning experiment tracking and visualization platform built with FastAPI (backend) and Vue 3 (frontend). The system supports both local visualization (via `swanlab watch`) and cloud deployment with multi-user collaboration, real-time data synchronization, and enterprise-grade features.

**Key Architecture**: Microservices-based deployment with Nginx (reverse proxy), FastAPI server, MySQL (structured data), ClickHouse (time-series metrics/logs), MinIO (media storage), Redis (auth/cache), and Fluent Bit (log collection).

```bash

docker-compose up -d

# Stop services
docker-compose down

docker-compose down -v
```

## Architecture & Code Organization

### Backend Structure (`swanboard/`)

**Layered Architecture Pattern**:

1. **`router/`** - FastAPI route definitions (thin controllers)
   - Routes map to `/api/v1/{resource}` endpoints
   - Each router file corresponds to a resource (projects, experiments, charts, etc.)
   - Authentication routes: `auth.py`, `oauth.py`, `api_key.py`

2. **`controller/`** - Business logic layer
   - Controllers orchestrate between services, repositories, and external systems
   - Handle request validation and response formatting
   - Example: `experiment.py` manages experiment lifecycle

3. **`services/`** - Reusable business services
   - `auth_service.py`: JWT tokens, password hashing (bcrypt)
   - `oauth_service.py`: GitHub OAuth integration

4. **`repositories/`** - Data access layer
   - Abstracts database operations from business logic
   - One repository per domain entity

5. **`db/`** - Database layer
   - `mysql/`: Peewee ORM models for structured data
     - `models.py`: Core models (Project, Experiment, Namespace, Chart, Tag)
     - `auth_models.py`: Authentication (Account, Tenant, RefreshToken)
     - `api_key_models.py`: API key management
   - `clickhouse.py`: Time-series data (metrics, logs)

6. **`middleware/`** - HTTP middleware
   - `common.py`: Response formatting, error handling, logging, param validation

7. **`dependencies/`** - FastAPI dependencies (auth, validation)

8. **`config/`** - Configuration classes
   - `auth_config.py`: JWT secrets, token expiration, Redis connection

9. **`utils/`** - Utility functions

10. **`template/`** - Compiled Vue frontend assets (generated by `npm run build.release`)

### Frontend Structure (`vue/src/`)

**Vue 3 + Vite + Pinia Architecture**:

- **`views/`**: Page-level components (route targets)
- **`components/`**: Reusable UI components
- **`charts/`**: Visualization components (using @antv/g2plot)
- **`business/`**: Business logic components
- **`layouts/`**: Layout wrappers
- **`router/`**: Vue Router configuration
- **`store/`**: Pinia state management
- **`api/`**: Axios HTTP client and API definitions
- **`i18n/`**: Internationalization (Vue-i18n)
- **`utils/`**: Frontend utilities
- **`assets/`**: Static assets (images, fonts)

### Database Models

**MySQL (via Peewee ORM)**:

Core tables (structured data):
- `cloud_namespaces`: User/organization workspaces
- `cloud_projects`: ML projects within namespaces
- `cloud_experiments`: Training runs with metadata
- `cloud_charts`: Chart configurations for metrics
- `cloud_tags`: Metric names and types
- `cloud_sources`: Data source configurations
- `cloud_displays`: Display settings for charts

Authentication tables:
- `accounts`: User accounts (email, hashed passwords)
- `tenants`: Workspaces/organizations
- `tenant_account_joins`: User-tenant membership (with roles)
- `account_integrates`: OAuth provider linkage (GitHub)
- `refresh_tokens`: JWT refresh token storage
- `api_keys`: API key management for programmatic access

**ClickHouse (time-series)**:
- Stores experiment metrics, logs, and large-scale time-series data
- Accessed via `clickhouse_driver` for high-performance analytics

### Key Configuration Files

- **`swanboard/settings.py`**: Server paths, file structure, MinIO config
- **`swanboard/app.py`**: FastAPI application setup, middleware registration, router mounting, lifecycle events (DB/Redis initialization)
- **`.env`**: Environment variables (database credentials, JWT secrets, OAuth keys)
- **`pyproject.toml`**: Python package config (uses Hatchling, version from `swanboard/package.json`)
- **`vite.config.js`**: Frontend build config (outputs to `swanboard/template/`)

### Authentication System

**Multi-tenant JWT-based authentication** (see `AUTH_IMPLEMENTATION_SUMMARY.md` for full details):

- Password authentication: bcrypt hashing with salt
- JWT tokens: Access tokens (1h default), refresh tokens (7d default)
- Redis-backed token storage (with DB fallback)
- OAuth support: GitHub (implemented), Google (reserved)
- Multi-tenancy: Users can belong to multiple workspaces with roles (owner/admin/member/viewer)
- API keys: For programmatic access (stored in `api_keys` table)

**Auth flow**:
1. Login → JWT access + refresh tokens
2. API requests → `Authorization: Bearer <access_token>`
3. Token refresh → Use refresh token to get new access token
4. OAuth → GitHub callback → Auto-create/link account

### API Endpoint Structure

Base path: `/api/v1`

**Resources**:
- `/project` - Project CRUD
- `/experiment` - Experiment management
- `/chart` - Chart configurations
- `/media` - Media file access
- `/namespace` - Workspace management
- `/cloud` - Cloud sync endpoints (used by SwanLab client's `EnhancedSwanBoardCallback`)
- `/auth` - Authentication (register, login, logout, refresh, /me)
- `/oauth` - OAuth flows (GitHub authorize/callback)
- `/api-keys` - API key management

**Documentation**:
- Swagger UI: `http://localhost:5173/api/docs`
- ReDoc: `http://localhost:5173/api/redoc`
- OpenAPI schema: `/api/v1/openapi.json`

### Host Mode & Data Sync

**Host mode** enables local training scripts to sync data to SwanLab-Server in real-time:

```python
import swanlab
run = swanlab.init(project="my-project", mode="host")
swanlab.log({"loss": 0.1})
```

**Data flow**:
- Training logs → Nginx (`/fluent-bit`) → Fluent Bit → ClickHouse
- Media files → MinIO (S3-compatible object storage)
- Experiment metadata → FastAPI (`/api/v1/cloud`) → MySQL

**Required environment variables**:
```bash
export SWANLAB_BASE_URL=http://localhost:22224
export SWANLAB_CLOUD_SYNC=true
export SWANLAB_API_KEY=<your_api_key>
```

## Build & Release Process

### Frontend Build Pipeline

1. Develop in `vue/src/`
2. Run `npm run build.release` (production mode)
3. Output artifacts written to `swanboard/template/` (index.html, assets/)
4. FastAPI serves compiled frontend from `template/` directory

### Python Package Release

1. Version defined in `swanboard/package.json` (e.g., "1.2.3")
2. `pyproject.toml` extracts version via Hatchling pattern matching
3. Build package: `python -m build` (creates sdist and wheel)
4. Publish: Push tag to `main` branch → GitHub Actions → PyPI

### Docker Image Build

- `Dockerfile` in root builds complete server image
- Includes backend, compiled frontend, and dependencies
- `docker/docker-compose.yml` orchestrates full stack

## Important Development Notes

### When Working with Models

- All Peewee models inherit from `CloudBaseModel` (defined in `swanboard/db/mysql/models.py`)
- Database connection is managed by `mysql_manager` singleton (from `swanboard/db/mysql/__init__.py`)
- Use `MySQLConfig.from_env()` to load DB credentials from environment variables
- ClickHouse operations are synchronous; use `clickhouse_driver.Client` for queries

### When Adding New API Endpoints

1. Create/update router in `swanboard/router/`
2. Implement business logic in `swanboard/controller/` or `swanboard/services/`
3. Add repository methods in `swanboard/repositories/` if needed
4. Register router in `swanboard/app.py` with appropriate prefix and tags
5. Use OpenAPI decorators (`@router.post`, `response_model`, etc.) for automatic docs

### When Modifying Frontend

- Auto-import enabled (unplugin-auto-import, unplugin-vue-components)
- Use Tailwind CSS classes for styling (config in `tailwind.config.js`)
- API calls go through `vue/src/api/` axios instances
- State management with Pinia (`vue/src/store/`)
- After changes, run `npm run build.release` to update backend template

### Environment Variables

Critical variables (see `.env.example` for full list):

**Database**:
- `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_DATABASE`
- `CLICKHOUSE_HOST`, `CLICKHOUSE_PORT`
- `REDIS_URL`

**Storage**:
- `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_BUCKET`

**Auth**:
- `JWT_SECRET_KEY` (generate with `python -c "import secrets; print(secrets.token_urlsafe(32))"`)
- `JWT_ACCESS_TOKEN_EXPIRES`, `JWT_REFRESH_TOKEN_EXPIRES`
- `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`

**Server**:
- `SWANLAB_BASE_URL` (e.g., `http://localhost:22224`)
- `SWANLAB_CLOUD_SYNC` (`true`/`false`)

## Common Pitfalls

1. **Frontend not updating**: Forgot to run `npm run build.release` after Vue changes
2. **Database connection errors**: Check `SWANLAB_CLOUD_SYNC` env var and MySQL credentials
3. **JWT errors**: Ensure `JWT_SECRET_KEY` is set and consistent
4. **Port conflicts**: Default ports are 5173 (dev server), 22224 (nginx), 3306 (mysql), 9000 (clickhouse), 9100 (minio)
5. **OAuth redirect mismatch**: GitHub OAuth callback must match `SWANLAB_BASE_URL/api/v1/oauth/github/callback`
